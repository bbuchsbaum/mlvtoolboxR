# Frozen subset designer benchmark v1

Frozen before optimizer implementation. Inputs are generated by
`inst/fixtures/designer-v1.R`; independent evaluation, exhaustive tiny references
and a ranked comparator are in `tools/designer/reference.R`. Source hashes are
retained with the freeze receipt. No natural drawings are included.

## Problem and constraints

Each whole contour is assigned to A, B, or unassigned. Conditions are disjoint.
The primary mode pools all contours across a drawing set; per-drawing mode
applies the same constraints separately to every source drawing. IDs are paired
with source drawing IDs. Geometry is never transformed or split.

Maximize the raw additive target difference `sum(target[A]) - sum(target[B])`.
V1 targets are integrated absolute curvature at the declared scale, contour
length, or length-integrated horizontal-minus-vertical orientation. Benchmarks
use integrated curvature, measured in geometric degrees. This is not an
independently normalized mean. Reporting a division by a common fixed target
length would preserve the optimizer; dividing by the separately achieved lengths
would change the objective and is outside v1.

Both conditions obey the same lower/upper retained-length and contour-count
bounds. An explicit count-imbalance limit may also apply. Matching uses absolute
length difference and L1 distances between **raw length-weighted histogram bin
masses**. Fixed bin ranges/units come from a shared `normalize=FALSE` feature
specification. For each nuisance bin, linear auxiliary variables can bound both
signs of the A-minus-B difference; their sum is bounded by the L1 tolerance.
Thus these constraints have a valid binary linear formulation. No independently
normalized histogram distances, union coverage, junctions, or MAT constraints
are accepted. Output reconstruction independently recomputes every residual.

## Fixed cases and comparison

The knapsack drawings contain elbow contours with lengths
`10,4,4,4,10,4,4,4` and turns `100,90,90,90,0,1,1,1`. Both conditions retain
8–12 pixels and 1–3 contours, with length difference at most 2, orientation
L1 distance at most 12, and count imbalance at most 2. The specification uses
two bins, a 0.1-pixel tent half-support, fixed length range 0–100, and no
normalization. One case uses one drawing; another splits the same contours
across unequal canvases. The intended optimum is 270 degrees versus ranked
100. These are transparent combinatorial counterexamples, not representative
natural-image performance estimates.

Controls include four tied straight contours, a two-drawing set with only one
contour in each, its provably infeasible per-drawing counterpart, a smaller
6–8-pixel budget, and a one-node search budget. Tiny exhaustive enumeration is
the independent optimum/infeasibility oracle. Known values are checked at freeze.

The comparator ranks by the same per-contour target and takes a whole-contour
prefix under the same maximum length/count budget. It stops at the first contour
that exceeds the length budget. A is selected first; B takes an ascending prefix
from the remainder, ensuring disjointness even with ties. IDs resolve ties.
It does not repair failed nuisance constraints. Infeasible baselines are reported
and cannot count as comparative wins.

The precommitted acceptance criterion is strict improvement greater than 1e-8
degrees on **both** feasible knapsack cases, at the same constraints, with no
loss on the feasible tie/small-set controls. Report every outcome, including the
infeasible comparator under the smaller budget. Do not change fixtures or
tolerances after inspecting optimizer results without a new version and receipt.

## Resources, status and scope

Every normal run has 5 seconds and 100,000 search nodes; the exhaustion control
has one node. Workspace cap: 200 MiB; benchmark process peak RSS is measured
separately. Selection is deterministic; no random seed or stochastic search is
used. No external solver is required for these bounded small inputs. A completed
exact search may certify optimality or infeasibility; an interrupted search must
report feasible-with-bound or exhausted-without-solution. Bounds may be loose.

Search effort limits apply to optimization, with preprocessing/verification time
reported separately. This release is a bounded whole-contour solver, not a
guarantee of tractability for large experiments. Transformation search, nonlinear
local search, spatial occupancy, relational objectives and perceptual validity
remain outside v1.
